- `dotnet new tool-manifest --output <dir>` writes `dotnet-tools.json` into `<dir>` itself, not `<dir>/.config/`; use `--output <repo-root>/.config` or move the file afterwards.
- `dotnet user-secrets init` writes a UTF-8 BOM into the csproj; strip it afterwards (`sed -i '1s/^\xEF\xBB\xBF//'`) unless the file already had one, to keep the diff minimal.
- The Write and Edit tools (and Bash heredocs written from tool input) turn `\uXXXX` sequences in source text into the literal characters (invisible ones included), and sed mangles the backslashes. To keep escapes in C# files, post-process with a node script that builds the backslash via `String.fromCharCode(92)`, then confirm ASCII only with `LC_ALL=C grep -c '[^ -~]' <file>`.
- A Bash heredoc that writes into a directory that does not exist yet fails silently, so run `mkdir -p` first.
- A test that only uses `Assert.Throws<SqliteException>` passes spuriously when the table is missing. Assert on the message or extended error code, so the red step fails for the right reason.
- A Bash heredoc containing escaped quotes (`\"`) can fail with "unexpected EOF". Create such C# files with the Write tool instead.
- EF Core `IsRequired()` makes the generated reader throw `InvalidOperationException` ("The data is NULL at ordinal N") on a NULL value even when the record property is nullable; casting to a nullable type in `Select` or using `EF.Property<T?>` does not change that.
- To read damaged rows (NULL in `IsRequired()` columns) through EF Core, use a separate keyless type with nullable, non-required properties, mapped with `HasNoKey()` and `ToView("<table>")`. It stays out of migrations, and a pending-model-changes check stays clean.
- EF Core 10 SQLite `MigrateAsync` honors the cancellation token while it waits for `__EFMigrationsLock`, so a timeout-linked `CancellationTokenSource` bounds the wait.
- `ConfigureTestServices` on `IWebHostBuilder` is in `Microsoft.AspNetCore.TestHost`, so add that using.
- A test factory cannot tell a default value from an explicit null in one signature, so use constructor overloads when null has a meaning.
- Simpler than post-processing escapes: build special characters in test sources with `((char)0x00A0).ToString()` or `char.ConvertFromUtf32(0x1F600)`, which keeps the file ASCII-only.
- `Process.Kill(entireProcessTree: true)` reliably stops `dotnet <dll>` children; after an exit, call the parameterless `WaitForExit()` so redirected output handlers are flushed before reading the captured text.
- In-process tests start the host (and so the `Program.cs` startup step) with one `factory.CreateClient()` in a `using`; dispose the factory in the test.
- `TestSecrets` passwords are 16 characters; slice with `[..12]` when a test needs exactly 12.
- Process tests run the built Api dll from `bin/<Configuration>/net10.0`: build the solution first; `--no-build` for quick reruns.
- In process tests, assert the behavior (log line, file exists) before reading the database, so a missing table does not mask the real reason with a `SqliteException`.
- In `AddInfrastructure`, read `ConnectionStrings:Default` through `sp.GetRequiredService<IConfiguration>()` inside the `AddDbContext((sp, options) => ...)` callback so test-factory overrides are seen; `DatabaseMigrator` (ctor takes a `TimeSpan`) is registered with a factory lambda.
- Top-level `Program.cs` can `return 0/1` and use static local functions before `public partial class Program;` while `WebApplicationFactory<Program>` keeps working; `AddUserSecrets<Program>(optional: true)` needs no extra package (shared framework).
